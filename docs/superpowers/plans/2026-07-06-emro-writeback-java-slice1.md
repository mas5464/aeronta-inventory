# eMRO Write-Back Service (Java) — Slice 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `services/emro-writeback-java/` — a Quarkus 3 / Java 21 service that applies Inventory Optimizer stock-level recommendations to the Trax eMRO Oracle DB with validation, idempotency, audit, JWT auth, and per-row results, over two REST facades (Trax IO #6 seam + PRD batch) and Kafka.

**Architecture:** One framework-free domain core (`StockLevelWriter`) fed by three thin entry points (2 REST facades + Kafka consumer), all normalizing to a canonical `WritebackCommand`. Writes are per-item `REQUIRES_NEW` transactions that upsert `PN_INVENTORY_LEVEL`, insert `PN_INVENTORY_LEVEL_AUDIT`, and insert a service-owned `WRITEBACK_LEDGER` row whose unique `idempotency_key` makes at-least-once delivery effectively-once.

**Tech Stack:** Quarkus 3.x (latest 3.x), Java 21, Hibernate ORM, Oracle (Dev Services: `gvenzl/oracle-free`), Flyway, SmallRye JWT, SmallRye Reactive Messaging (Kafka; Dev Services: Redpanda), Micrometer + OpenTelemetry, Lombok, JUnit 5 + RestAssured + KafkaCompanion.

**Spec:** [docs/superpowers/specs/2026-07-06-emro-writeback-java-slice1-design.md](../specs/2026-07-06-emro-writeback-java-slice1-design.md)
**ARMAC reference source (read-only, outside repo):** `/Users/miguelsosa/trax-mgmt-armac_interfaces/ROLEOQUpdateService/src/main/java/trax/aero/`
**Python contract source (in-repo, authoritative for Facade 1):** `services/agent-spine/src/trax_io_spine/writeback/{contracts.py,rest.py,fake_emro.py}`

## Global Constraints

- Java **21**, Quarkus **3.x** (use latest 3.x platform BOM at implementation time), single Maven module at `services/emro-writeback-java/`.
- **Never** issue DDL against eMRO tables (`PN_INVENTORY_LEVEL`, `PN_MASTER`, …). Flyway manages **only** `WRITEBACK_LEDGER`. Test schemas are generated by Hibernate in the disposable test DB only.
- **Never** manage (stop/restart/remove) the local `oracle19c` Docker container — connect only, and only in the env-gated smoke test.
- JWT required on **every** endpoint except `/q/health*`. Roles: `writeback:write` (apply/batch/ingest paths), `writeback:read` (history).
- Facade 1 wire format is **snake_case** and must match `services/agent-spine` contracts **exactly** (int values, field names, status strings). Facade 2 (batch) is camelCase.
- Per-item transactions: `@Transactional(REQUIRES_NEW)` in the writer; no batch-wide transaction.
- Duplicates are success-shaped: batch → `SKIPPED_DUPLICATE`; Facade 1 replay → **the original result** (contract-pinned).
- Rejected rows are **not** ledgered (a corrected retry with the same `runId:rowId` must be able to succeed); only applied/shadowed writes consume an idempotency key.
- Conventional commits; commit after every green task.
- All Maven commands run from `services/emro-writeback-java/`. Docker must be running (Dev Services).

### Documented contract deviations (carried into ADR, Task 13)

1. Facade 1 never emits `409 deferred_open_order` in slice 1 (open-order deferral is enforced upstream by the Supervisor; `RestWritebackClient` handles-but-does-not-require it).
2. `HistoryEntry.agent_version` is `"emro-writeback-java/1.0"` (fake_emro hardcodes `"agent-spine-v1"`; the field identifies the writer, so each writer reports itself).
3. History is served **ledger-only** in slice 1; the audit-table supplement for out-of-band writers moves to slice 2 with rollback (fabricating `version` ints for out-of-band edits needs the rollback design). Spec §4.1 gets a one-line amendment (Task 13).

```java
// Provenance.java
package trax.io.writeback.domain;

public record Provenance(String tenantId, String source, String runId, Long rowId,
                         String provenanceId, String explicitIdempotencyKey,
                         Integer tier, String approver, String principal) {
    public String idempotencyKey() {
        if (explicitIdempotencyKey != null && !explicitIdempotencyKey.isBlank()) return explicitIdempotencyKey;
        if (runId != null && !runId.isBlank() && rowId != null) return runId + ":" + rowId;
        throw new IllegalStateException("no idempotency key: need explicitIdempotencyKey or runId+rowId");
    }
}
```

```java
package trax.io.writeback.domain;

import java.math.BigDecimal;
import java.math.RoundingMode;

public final class NumericPolicy {
    private NumericPolicy() {}
    public static BigDecimal apply(BigDecimal value, boolean consumable) {
        if (value == null || consumable) return value;
        return value.setScale(0, RoundingMode.DOWN);
    }
}
```

**Files:**

**Pipeline (implementation contract):**
1. Validate: PN active (`REJECTED_UNKNOWN_KEY` if absent, `REJECTED_VALIDATION` if inactive-status message), location active-inventory & not quarantine, all present numerics ≥ 0, `stockMin ≤ stockMax` and `orderMin ≤ orderMax` when both present.
2. Duplicate check: `findByIdempotencyKey` → if present, return `SKIPPED_DUPLICATE` carrying the ledger row's old/new values + version.
3. Load existing `PnInventoryLevel` (nullable) → capture `oldValues` map (`rop/eoq/safety_stock/max_stock` ints from `REORDER_LEVEL/EOQ_LEVEL/MINIMUM_STOCK/MAXIMUM_STOCK`, `setScale(0, HALF_UP).intValueExact()`); null when no row existed.
4. Apply `NumericPolicy` per field (consumable via `repo.isConsumable(pnMaster.category)`); **null command field ⇒ column untouched** (existing value preserved; stays null on a new row).
5. If `cmd.shadow()`: **no eMRO write** — ledger row outcome `SHADOWED` with old/new values, version chaining as below → `ItemResult(SHADOWED, 200, …)`.
6. Else upsert entity (create if absent; `company = repo.company()`, `createdBy/modifiedBy = provenance.principal()`, dates now) via `persistOrMerge`, then insert `PnInventoryLevelAudit` row mirroring the level.
7. Ledger insert (same tx): outcome `WRITTEN`/`SHADOWED`, `version = 1 + max(version)` for the `(tenantId, pn, location)` key (0 rows ⇒ 1), `parentVersion` = previous max or null, values JSON via Jackson `ObjectMapper`, `agentVersion = "emro-writeback-java/1.0"`.
8. `SQLIntegrityConstraintViolationException` (concurrent duplicate) is caught **by the caller of** `writeItem` (facades/consumer) since the tx must roll back: catch `jakarta.transaction.RollbackException`/persistence exception whose cause chain contains the constraint name `UQ_WRITEBACK_IDEMPOTENCY` → re-fetch ledger row → `SKIPPED_DUPLICATE`. Provide `public ItemResult writeItemDedup(WritebackCommand cmd)` wrapper (non-transactional) doing exactly this — **facades call `writeItemDedup`**.
9. Any other exception → `ItemResult(ERROR, 500, exception message, …)` from the wrapper; tx rolled back.

**Wire contract (authoritative, extracted from agent-spine):**

Request (`WritebackRequest`, snake_case, values are non-negative **ints**):
```json
{"tenant_id":"acme","pn":"PN-A","location":"LOC-1","rop":5,"eoq":4,"safety_stock":2,"max_stock":12,
```

Field mapping: `rop→REORDER_LEVEL`, `eoq→EOQ_LEVEL`, `safety_stock→MINIMUM_STOCK`, `max_stock→MAXIMUM_STOCK`. `tier` on this wire is the Python `AutonomyTier` string (`"advisor"|"bounded"|"autonomous"`) or null — store as-is in ledger `APPROVER`-adjacent… **no**: store the string in a dedicated mapping: `Provenance.tier` is `Integer` (batch uses ints); for Facade 1 map `"advisor"→1, "bounded"→2, "autonomous"→3`, null→null.

Response 200 (`WritebackResult`):
```json
{"tenant_id":"acme","pn":"PN-A","location":"LOC-1","status":"written",
 "old_values":null,"new_values":{"rop":5,"eoq":4,"safety_stock":2,"max_stock":12},
 "written_at":"2026-04-01T12:34:56.789123+00:00","error_message":null}
```

**Semantics:**
- `ACCEPTED → "written"`, `SHADOWED → "shadowed"`.
- `SKIPPED_DUPLICATE` → **replay the original**: status `"written"` (or `"shadowed"` per ledger outcome), old/new values from the ledger row, 200. (Pinned by agent-spine's `test_idempotent_replay`.)

**Implementation contract:**
```java
@ApplicationScoped
public class WritebackConsumer {
    @Inject BatchProcessor processor;
    @Inject ObjectMapper mapper;
    @Channel("writeback-results") Emitter<String> results;
    @Channel("writeback-dlq") Emitter<String> dlq;

    @Incoming("writeback-in")
    @Blocking
    public void consume(String payload) {
        BatchRequest req;
        try { req = mapper.readValue(payload, BatchRequest.class); }
        catch (Exception parse) { dlq.send(payload); return; }   // poison → DLQ, ack
        BatchResponse resp = processWithRetry(req);              // 3 attempts, 200ms/800ms/3200ms backoff
        try { results.send(mapper.writeValueAsString(resp)); } catch (Exception impossible) { throw new RuntimeException(impossible); }
    }
    // processWithRetry: catches RuntimeException from processing; after 3rd failure → dlq.send(payload)
    // principal for Kafka-ingested items = "kafka-ingest"; tenantId from BatchRequest? No — BatchRequest has no tenant field:
    // add OPTIONAL "tenantId" to BatchRequest (null → "default"); REST path ignores it in favor of the JWT claim.
}
```
